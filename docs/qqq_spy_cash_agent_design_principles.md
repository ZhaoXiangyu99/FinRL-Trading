# QQQ / SPY / 现金交易 Agent 设计原则

> 状态：Design Baseline v0.1
> 日期：2026-07-29
> 适用范围：FinRL-Trading 中面向 QQQ、SPY 和现金的长期组合管理 Agent

本文档是后续实现、回测、模拟交易和实盘评审共同遵守的设计契约。它不是盈利证明，也不代表任何模型已经具备实盘部署条件。

## 1. 核心目标

Agent 每个交易日根据截至决策时刻已经公开的信息，决定下一执行时点的目标组合：

- QQQ 权重
- SPY 权重
- 现金权重

系统的长期目标是在扣除真实交易成本后，以可控风险持续改善相对于 QQQ 和 SPY 买入持有策略的表现。

首个版本遵循以下硬边界：

- 只允许持有 QQQ、SPY 和现金。
- 只做多，不做空，不使用杠杆。
- 策略输出目标权重，不直接输出订单。
- 风险引擎可以否决、缩小或延迟策略建议。
- 实盘订单必须经过人工确认。
- 实盘 Champion 模型保持冻结，不在真实资金上即时修改参数。
- “持续学习”发生在离线 Challenger 中，通过评审后才能替换 Champion。

## 2. “Agent 每天看到的状态”是什么意思

状态是 Agent 做出当天决策之前能够看到的一张数值化快照。

例如，在交易日 `t` 收盘后生成决策时，状态只能使用当时已经确定并可获得的数据；Agent 不能看到 `t+1` 的价格、未来修订值或本半年最终收益。

状态不是让大语言模型自由阅读新闻后直接交易，而是一个有明确字段、时间戳和版本的数据结构。相同状态输入应能被稳定复现。

### 2.1 市场状态

QQQ 和 SPY 分别包含：

- 5、20、60、120 个交易日的总回报率。
- 20、60 个交易日的实现波动率。
- 相对 50、120、200 日均线的位置。
- 距离近期高点的回撤幅度。
- 成交量相对近期均值的变化。

跨资产状态包含：

- QQQ 相对 SPY 的 20、60、120 日强弱。
- QQQ 与 SPY 的滚动相关性。
- 两者近期波动率之差。

### 2.2 当前组合状态

- 当前 QQQ、SPY、现金权重。
- 本半年度截至当前的组合净收益。
- 同期 QQQ、SPY 买入持有总收益。
- 组合相对两个基准的超额收益。
- 本半年度最大回撤。
- 本半年度累计换手率和交易成本。
- 距离半年度结算还剩多少交易日。

### 2.3 风险环境状态

可以加入 VIX、利率、信用利差、市场宽度等变量，但它们只用于描述风险环境和约束仓位，不得单独触发买卖。

**宏观变量目前只有环境过滤作用，尚无稳定样本外交易优势。**

### 2.4 状态数据的硬要求

- 每个字段必须记录观测时间和最早可用时间。
- 价格口径必须统一处理拆股和分红。
- 决策时间、信号时间和成交时间必须分开记录。
- 默认在下一个可交易时点成交，禁止用产生信号的同一收盘价假设无摩擦成交。
- 所有状态字段需要版本号；字段增删后不得与旧模型静默混用。
- 缺失值处理必须预先定义，不能在回测中临时选择对结果更有利的方法。

## 3. 动作空间：Agent 能做什么

动作是下一执行时点希望持有的目标权重：

```text
action = [weight_qqq, weight_spy, weight_cash]
```

必须始终满足：

```text
weight_qqq >= 0
weight_spy >= 0
weight_cash >= 0
weight_qqq + weight_spy + weight_cash = 1
```

首版使用 25% 步长的离散动作，以降低训练难度并提高可解释性。动作集合对 QQQ 和 SPY 保持对称，避免把开发者偏好偷偷写进动作空间：

| 动作 | QQQ | SPY | 现金 |
|---|---:|---:|---:|
| A00 | 0% | 0% | 100% |
| A01 | 0% | 25% | 75% |
| A02 | 0% | 50% | 50% |
| A03 | 0% | 75% | 25% |
| A04 | 0% | 100% | 0% |
| A05 | 25% | 0% | 75% |
| A06 | 25% | 25% | 50% |
| A07 | 25% | 50% | 25% |
| A08 | 25% | 75% | 0% |
| A09 | 50% | 0% | 50% |
| A10 | 50% | 25% | 25% |
| A11 | 50% | 50% | 0% |
| A12 | 75% | 0% | 25% |
| A13 | 75% | 25% | 0% |
| A14 | 100% | 0% | 0% |

策略选择目标权重后，风险引擎仍可执行：

- 最大风险资产仓位限制。
- 最小现金比例限制。
- 单次调仓幅度限制。
- 回撤状态下的降仓。
- 异常数据、停牌或流动性不足时的否决。

是否设置“权重偏差不足某个阈值则不调仓”，应通过交易成本敏感性测试决定，不能只为提高回测收益临时调整。

## 4. 半年度奖励原则

一个主要评估周期为固定的半年度：

- 上半年：第一个可交易日至 6 月最后一个可交易日。
- 下半年：7 月第一个可交易日至 12 月最后一个可交易日。

设：

- `R_p`：组合在本半年度扣除成本后的总收益。
- `R_spy`：同期 SPY 买入持有总收益。
- `R_qqq`：同期 QQQ 买入持有总收益。
- `alpha_strong = R_p - max(R_spy, R_qqq)`。
- `alpha_weak = R_p - min(R_spy, R_qqq)`。

### 4.1 奖惩分层

奖励不能只与单一基准比较，否则模型会利用 QQQ 和 SPY 风格差异“挑软柿子”。首版遵循三级结算：

1. **跑赢两者**：`alpha_strong > 0`，给予完整正奖励。
2. **只跑赢一个**：`alpha_weak > 0` 且 `alpha_strong <= 0`，给予较小奖励或近中性反馈。
3. **两者都未跑赢**：`alpha_weak <= 0`，给予惩罚。

奖励大小应随超额收益单调变化，但必须归一化并设置上下限，避免某个极端半年支配整个训练过程。

### 4.2 风险与成本

不能为了跑赢基准而无限放大风险。最终结算分数还应考虑：

- 最大回撤。
- 下行波动或尾部损失。
- 违反仓位约束的行为。
- 必要时加入独立的换手率正则项。

交易手续费、滑点和价差首先直接计入 `R_p`。如果另外加入换手惩罚，必须明确它是行为正则，而不是把同一交易成本重复扣除两次。

一个方向性的终局评分形式可以是：

```text
terminal_score =
    benchmark_relative_score(alpha_strong, alpha_weak)
    - drawdown_penalty
    - tail_risk_penalty
    - constraint_violation_penalty
    - optional_turnover_regularizer
```

具体系数在首轮环境测试后再冻结，当前不凭直觉指定。

### 4.3 为什么不能只在半年最后一天给一次奖励

如果约 126 个交易日内只有最后一天收到反馈，学习信号过于稀疏，单卡训练也会浪费大量样本。

可以使用“势函数差分”生成日度反馈：

```text
dense_reward_t = Phi(state_t) - Phi(state_t_minus_1)
```

其中 `Phi` 只使用截至当天的组合表现、同期基准表现和风险状态。整个半年度的差分累加后，仍应与最终结算目标一致，不能另造一个短线目标。

因此：

- 半年度终局分数是最终目标和模型晋级依据。
- 日度奖励只是帮助模型理解行动后果。
- 日度奖励不得使用本半年未来的最终基准收益。
- 硬性约束违规可以即时处罚。

### 4.4 奖励函数的情景验收

在写训练代码前，至少验证下列排序：

| 场景 | SPY | QQQ | 组合 | 预期 |
|---|---:|---:|---:|---|
| 牛市且跑赢两者 | 8% | 11% | 14% | 完整奖励 |
| 只跑赢 SPY | 8% | 11% | 10% | 小奖励或近中性 |
| 两者都未跑赢 | 8% | 11% | 5% | 惩罚 |
| 熊市中少亏 | -8% | -15% | -5% | 完整奖励 |
| 熊市中只跑赢 QQQ | -8% | -15% | -10% | 小奖励或近中性 |

这意味着奖励衡量的是相对管理能力，而不是简单地把“正收益”当成成功。

## 5. 持续实盘学习的安全架构

“通过不断实盘学习”不等于让正在控制真实资金的模型每天自行改写参数。

推荐采用 Champion / Challenger：

### 5.1 Champion

- 当前获准用于模拟或实盘建议的冻结模型。
- 只负责生成目标权重建议。
- 经过风险引擎和人工审批后才可能产生订单。
- 模型版本、状态版本和配置必须可以追溯。

### 5.2 数据闭环

每天记录：

- 当时的原始状态和特征状态。
- Champion 提议的目标权重。
- 风险引擎的否决或修改。
- 人工接受、修改或拒绝的结果。
- 计划成交与实际成交。
- 手续费、滑点、持仓和净值。
- 1、5、20 日后结果以及半年度最终结果。

人工决策不能直接当成“正确答案”，只能作为一类辅助信号；否则模型只会复制人的既有偏差。

### 5.3 Challenger

- 使用新增实盘数据和历史数据离线训练候选模型。
- 可以定期训练，但不得未经评审直接替换 Champion。
- 数据量不足时优先积累证据，不因“到了更新时间”强行换模型。

### 5.4 晋级门槛

Challenger 至少通过以下门槛，才可由人工批准晋级：

- 严格的滚动样本外测试，并对训练期与验证期做时间隔离。
- 扣除费用和滑点后，与 QQQ、SPY 买入持有比较。
- 未使用未来数据、未来修订数据或同价成交泄漏。
- 模拟盘或影子运行通过。
- 收益改善不是以明显恶化最大回撤、尾部风险或换手率为代价。
- 在多个市场阶段有效，不由单一幸运半年决定。
- 所有数据、代码、参数和随机种子可复现。

实盘中的新数据主要用于产生更真实的训练样本和执行反馈，而不是给在线探索提供试错资金。

## 6. 为什么首版不以 Agentic-RL 为核心

首版真正需要的是一个受约束的组合决策问题。标准强化学习环境已经能够表示：

- 状态：市场、组合和风险环境。
- 动作：QQQ、SPY、现金的目标权重。
- 奖励：半年度相对收益与风险约束。
- 转移：市场变化、调仓成本和组合净值变化。

Agentic 能力更适合外围工作，例如：

- 数据质量检查。
- 回测和训练任务编排。
- Challenger 实验总结。
- 异常原因调查。
- 生成人工审批材料。

不应让大语言模型通过自由文本推理绕过确定性的动作约束、风险引擎或人工审批。只有在基础 RL 系统形成可靠基线后，才评估 Agentic 层是否带来可测量的增益。

## 7. 编码前的验收条件

进入训练实现前，必须先通过以下设计验收：

- [ ] 每个状态字段都有定义、单位、窗口、观测时间和最早可用时间。
- [ ] 动作映射只产生合法的 QQQ、SPY、现金权重，并对 QQQ/SPY 对称。
- [ ] 决策时点、执行时点、价格口径和分红口径已冻结。
- [ ] 手续费、滑点、价差和现金收益假设已冻结。
- [ ] 半年度奖励的情景测试满足预期排序。
- [ ] 日度密集奖励累加后不改变半年度终局目标。
- [ ] 回测同时报告 QQQ 和 SPY 买入持有基准。
- [ ] 报告总收益、最大回撤、换手率、交易成本和半年度胜率。
- [ ] 训练、验证、测试按时间隔离并执行泄漏检查。
- [ ] 策略输出不能直接创建真实订单。
- [ ] Champion 的替换必须经过风险评审和人工批准。
- [ ] 实验数据、代码、配置、模型和随机种子可以复现。

## 8. 尚待冻结的参数

以下问题应在环境契约和测试阶段明确，不在本原则文档中武断决定：

- 半年度奖励各部分的归一化、上限和权重。
- 现金按零收益还是短期无风险利率计息。
- 基准是否计入初始建仓成本。
- 调仓频率及最小调仓阈值。
- 决策使用收盘后数据时的具体执行价格。
- 最大回撤、最大风险资产仓位和最低现金限制。
- Challenger 的训练频率、影子运行长度和正式晋级频率。

任何参数一旦用于正式样本外评估，就必须冻结；不能根据测试结果反复调整后仍把同一测试期称为“样本外”。

## 9. 下一步

下一步不是立即训练，而是实现一个最小的“三资产环境契约”和自动化测试：

1. 明确定义状态与动作的数据结构。
2. 实现交易日推进、目标权重调仓、成本和净值计算。
3. 实现半年度终止与奖励接口。
4. 用手工构造的价格路径验证无未来数据、动作约束和奖励排序。
5. 环境测试通过后，再接入真实历史数据并选择一个轻量 RL 基线。
